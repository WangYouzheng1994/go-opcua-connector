# Go 项目工程规范

## 注释规范（遵循 Go 社区标准）

### 包注释
- 每个包必须有包注释，放在 `package` 声明之前
- 格式：`// Package 包名 包功能描述`
- 对于 `main` 包：`// Command 命令名 命令功能描述`
- 包注释可放在包内任意一个文件中，推荐使用独立的 `doc.go` 文件

### 类型（结构体/接口）注释
- 导出类型必须有注释，格式：`// TypeName 类型描述`
- 注释紧邻类型声明之前，之间不能有空行
- 多行描述示例：
```go
// Collector 数据采集器
// 订阅+拉取复合模式：
// - 订阅：实时接收数据变化
// - 拉取：定期心跳验证
type Collector struct {
```

### 函数/方法注释
- 导出函数/方法必须有注释，格式：`// FuncName 功能描述`
- 注释紧邻函数声明之前，之间不能有空行
- 多行描述：后续行同样以 `//` 开头

### 结构体字段注释
- 每个字段必须有注释说明
- 格式：`// FieldName 字段描述`
- 注释放在字段声明上方一行

### 禁止项
- **禁止** 使用 Java 风格的 `/** */` 块注释
- **禁止** 使用 `@author`、`@param`、`@return` 等 Javadoc 标签
- **禁止** 在代码行尾部添加注释（行尾注释），注释必须换行
- **禁止** 无意义的注释（如仅重复类型名或函数名）

### 注释书写要求
- 注释必须是完整的句子，以 `.` 结尾（英文注释）或以句号结尾（中文注释）
- 注释首字母大写（英文），中文直接书写
- 注释统一使用 UTF-8 编码

## 代码风格规范

### 命名规范
- 包名：全小写，无下划线，简短有意义
- 导出标识符：遵循驼峰命名法（CamelCase），首字母大写
- 非导出标识符：遵循驼峰命名法（camelCase），首字母小写
- 常量：驼峰命名法，不使用全大写，不使用下划线

### 代码组织
- 每个文件只能属于一个包
- import 分组：标准库 → 第三方库 → 本项目包，组间空行分隔
- 使用 `goimports` 或 `gofmt` 自动格式化代码

### 编译要求
- 代码修改后必须通过 `go build ./...` 编译
- 代码修改后必须通过 `go vet ./...` 静态检查

## 编译与检查命令
```bash
# 编译检查
go build ./...

# 静态分析
go vet ./...
```
